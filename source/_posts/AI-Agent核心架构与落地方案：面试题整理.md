# AI Agent 核心架构与落地方案：面试题整理

> 整理自抖音视频：[面试官问：AI Agent 常见核心架构与落地方案有哪些？](https://www.douyin.com/jingxuan?modal_id=7676931818318318863)

## 一、面试中的推荐回答

AI Agent 的核心不是简单地调用一次大模型，而是让模型围绕目标进行任务拆解、工具调用、结果观察和必要的纠错。实际落地时，需要在**任务完成能力、执行效率、响应延迟和调用成本**之间做平衡。

常见架构可以分为五类：

1. 工具调用型
2. 流程编排型
3. 规划推理型
4. 记忆增强型
5. 多智能体协作型

工程实践中还会叠加分级调度、反思纠错、工具容错和降级策略。

## 二、工具调用型架构

工具调用型架构由大模型负责理解用户意图，并根据需要选择工具，例如搜索、数据库查询、代码执行或业务 API。

典型流程如下：

```text
用户问题
  -> 大模型判断是否需要工具
  -> 生成工具名称与参数
  -> 执行工具
  -> 将工具结果返回给大模型
  -> 生成最终答案
```

这种架构实现简单、链路短、成本较低，适合天气查询、订单查询、知识库问答等任务。

它的局限是自主规划能力有限。面对需要多个步骤的复杂任务时，通常需要业务代码明确规定调用顺序。

## 三、流程编排型架构

流程编排型架构把业务流程拆成固定节点，由工作流引擎或业务代码控制执行顺序。大模型负责其中的理解、分类、内容生成等环节。

例如，一个客服工单流程可以是：

```text
识别问题类型
  -> 查询用户信息
  -> 查询订单状态
  -> 判断是否满足退款条件
  -> 生成回复
  -> 创建或关闭工单
```

优点是执行过程可控、容易测试、便于审计，也更适合金融、客服和内部运营等对确定性要求高的场景。

缺点是灵活性较弱。遇到没有预先设计的任务路径时，系统无法像规划型 Agent 一样临时拆解问题。

## 四、规划推理型架构

规划推理型架构允许大模型先拆解任务，再逐步执行。每一步都可以根据工具结果决定下一步行动。

```text
理解目标
  -> 拆解子任务
  -> 执行当前步骤
  -> 观察结果
  -> 调整计划
  -> 完成任务
```

它适合研究分析、复杂检索、代码生成与调试等开放性任务，能够处理事先没有完全定义的执行路径。

代价是推理轮次更多，带来更高的延迟和 Token 成本。每增加一轮模型调用，也会增加工具失败、循环调用和结果偏离的可能性。因此需要设置最大步数、超时、预算和终止条件。

## 五、记忆增强型架构

记忆增强型架构会保存 Agent 过去的任务结果、用户偏好或中间经验，在后续任务中检索并复用。

常见的记忆可以分成三类：

- 短期记忆：当前会话中的上下文和工具结果。
- 长期记忆：用户偏好、历史任务和稳定事实。
- 工作记忆：当前任务的计划、状态和待办步骤。

记忆可以提升连续任务中的效率和一致性，但真正的难点在于记忆管理：哪些内容值得保存、如何检索、如何更新过期信息，以及如何避免错误记忆被反复使用。

因此，记忆系统需要考虑来源、时间、可信度和失效机制，不能把所有历史对话都直接塞进上下文。

## 六、多智能体协作型架构

多智能体架构会把复杂目标分给不同角色的 Agent。例如：

```text
主 Agent：拆解任务与协调结果
研究 Agent：搜索和整理资料
执行 Agent：调用业务工具
审核 Agent：检查结果质量
```

这种方式可以让角色职责更清晰，也适合研究、内容生产和复杂业务流程。但通信成本、状态同步和错误传播会随 Agent 数量增加而上升。

实际使用时，应先确认单 Agent 是否已经足够。只有当任务边界清楚、角色确实需要分工时，多智能体才有意义。

## 七、分级调度：平衡效果与成本

不同任务不应使用同一套模型和同一套推理深度。分级调度可以先判断任务难度，再选择合适的 Agent 或模型。

```text
简单问题 -> 轻量模型 + 单次工具调用
中等问题 -> 工作流 + 有限推理
复杂问题 -> 强模型 + 规划推理 + 反思
```

分级调度的目标不是让每个任务都得到最复杂的处理，而是让简单任务快速完成，把计算资源留给真正复杂的问题。

## 八、自我反思与纠错

在复杂任务中，Agent 可以增加一个反思步骤，对执行结果进行检查：

1. 当前结果是否满足原始目标？
2. 工具返回的数据是否完整？
3. 是否存在事实错误或遗漏？
4. 是否需要重新执行某一步？

反思机制可以提升复杂任务的成功率，但会增加模型调用次数。工程上需要限制反思次数，并区分哪些错误值得重试，避免 Agent 在错误路径中循环。

## 九、工具容错与降级

生产环境中，工具调用失败是常态，需要提前设计容错机制：

- 设置超时和最大重试次数。
- 对临时网络错误使用指数退避。
- 对参数错误返回结构化错误信息，让模型修正参数。
- 为关键工具准备备用接口或缓存结果。
- 连续失败时停止调用并向用户说明当前限制。
- 对高风险操作增加人工确认或权限校验。

降级策略的目标是让 Agent 在部分能力不可用时仍能给出可控结果，而不是继续无休止地调用工具。

## 十、如何根据场景选型

| 业务场景 | 推荐架构 | 主要原因 |
| --- | --- | --- |
| 查询天气、订单、库存 | 工具调用型 | 链路短，结果明确 |
| 客服工单、审批流程 | 流程编排型 | 路径可控，便于审计 |
| 深度研究、代码调试 | 规划推理型 | 需要任务拆解和动态决策 |
| 个性化助手、长期陪伴 | 记忆增强型 | 需要复用用户历史信息 |
| 复杂研究和内容生产 | 多智能体协作型 | 任务可以按角色拆分 |

选型时可以从四个问题开始：

1. 任务路径是否固定？
2. 是否需要调用外部工具？
3. 任务是否需要跨会话记忆？
4. 结果是否需要多角色审核？

简单场景优先使用轻量架构。任务变复杂后，再按需增加规划、记忆、反思和多智能体能力。

## 十一、面试总结

回答 AI Agent 架构题时，可以按照“定义、分类、取舍、落地保障”的顺序回答：

> AI Agent 是围绕目标自主完成任务的系统，通常包含大模型、工具、状态管理和执行循环。架构上可以分为工具调用、流程编排、规划推理、记忆增强和多智能体协作五类。简单任务使用工具调用或固定流程，复杂任务使用规划推理，跨会话场景引入记忆，需要角色分工时采用多智能体。生产环境还要补充分级调度、超时重试、反思纠错、权限控制和降级策略，在任务成功率、延迟和成本之间取得平衡。

这类回答既覆盖了概念，也体现了工程落地意识。
